Temat: Badanie protokołów WWW

Cel i zakres

Celem ćwiczenia było poznanie działania protokołu HTTP, ręczne wysyłanie żądań przez PuTTY, użycie curl, analiza URL, cookies, proxy, HTTPS, wyszukiwarek oraz podstaw HTML/CSS.

Badanie działania HTTP przez PuTTY

Zapoznano się z dokumentami RFC dotyczącymi HTTP/1.0, HTTP/1.1 i HTTP/2. Następnie przez PuTTY połączono się z serwerem WWW w trybie RAW na porcie 80.

GET /~sNrIndeksu/ HTTP/1.1
Host: mts.wibro.agh.edu.pl
PróbaOczekiwana odpowiedźKomentarz
Poprawne żądanie GET200 OK lub inny poprawny kod dla istniejącego zasobuSerwer odsyła nagłówki i treść strony.
Błędny nagłówek400 Bad Request lub odrzucenie żądaniaSerwer nie potrafi poprawnie zinterpretować zapytania.
Niepoprawny adres strony404 Not FoundŻądany zasób nie istnieje.
Niepoprawny hostbłąd hosta, przekierowanie albo strona domyślnaWirtualne hosty wymagają poprawnego nagłówka Host.

HTTP jest protokołem bezstanowym: każde żądanie jest niezależne od poprzedniego. Po zmianie opcji PuTTY Close window on exit na Always połączenie po obsłużeniu żądania może zostać zamknięte, co dobrze pokazuje jednorazowy charakter typowej komunikacji HTTP.

Badanie odpowiedzi przez curl

Polecenie curl umożliwia wykonywanie żądań HTTP/HTTPS z konsoli. Do wyświetlenia nagłówków użyto opcji -I lub -i.

curl -I http://mts.wibro.agh.edu.pl/~sNrIndeksu/
curl -i http://mts.wibro.agh.edu.pl/~sNrIndeksu/
curl -L -I https://example.com/
NagłówekZnaczenie
Status / linia statusuKod odpowiedzi, np. 200 OK, 301 Moved Permanently, 404 Not Found.
Content-TypeTyp zwracanych danych, np. text/html; charset=UTF-8.
Content-LengthRozmiar odpowiedzi w bajtach, jeśli serwer go podaje.
ServerInformacja o oprogramowaniu serwera WWW.
Set-CookieUstawienie pliku cookie po stronie przeglądarki.

Definicja URL i przykłady odwołań

URL to ustandaryzowany adres zasobu. Składa się m.in. ze schematu, hosta, opcjonalnego portu, ścieżki, zapytania i fragmentu.

https://www.example.com:443/katalog/plik.html?x=1#sekcja
mailto:login@student.agh.edu.pl
<img src="img/obraz.png" alt="Opis grafiki">
<a href="#sekcja">Przejdź do sekcji</a>
SkładnikPrzykładZnaczenie
SchemathttpsProtokół dostępu.
Hostwww.example.comNazwa serwera.
Port443Port usługi, opcjonalny.
Ścieżka/katalog/plik.htmlPołożenie zasobu na serwerze.
Query?x=1Parametry przekazywane do aplikacji.
Fragment#sekcjaOdwołanie do elementu strony o podanym id.

Test szybkości ładowania wykonano w narzędziach PageSpeed Insights dla ponizszych stron:

Pliki cookie są małymi porcjami danych zapisywanymi przez przeglądarkę. Służą m.in. do sesji logowania, preferencji użytkownika, koszyka zakupowego i analityki. Po wyłączeniu cookies część serwisów traci możliwość zapamiętywania zalogowania lub ustawień.

Serwer proxy może pośredniczyć w ruchu, filtrować treści, ukrywać adres klienta, buforować odpowiedzi i egzekwować polityki bezpieczeństwa. HTTPS różni się od HTTP dodaniem warstwy TLS, która zapewnia szyfrowanie, integralność i uwierzytelnienie serwera certyfikatem.

Modyfikacja strony HTML/CSS i wnioski

Stronę użytkownika rozbudowano o listy, tabele, formularz, obrazki i style CSS.

<link rel="stylesheet" href="style.css">
<ul><li>Element listy</li></ul>
<table><tr><th>Kolumna</th></tr><tr><td>Dane</td></tr></table>
<form action="#" method="post">
  <label>Imię <input name="imie" type="text"></label>
  <button type="submit">Wyślij</button>
</form>

Wniosek: HTTP można łatwo obserwować na poziomie tekstowym, natomiast HTTPS zabezpiecza transmisję przed podsłuchem. Poprawne użycie nagłówków, kodowania i zasobów CSS/HTML wpływa zarówno na działanie, jak i wydajność strony.
